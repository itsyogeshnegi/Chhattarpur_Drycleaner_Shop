# AL-HARAM Drycleaner's And Launderettes — Web App & Back-Office CMS

Full-stack web application and store management POS for **AL-HARAM Drycleaner's And Launderettes** (Chattarpur, New Delhi), built with **Next.js (App Router)**, **React 19**, **Tailwind CSS** (`Poppins` typography), and **MongoDB / Mongoose**.

---

## Executive Summary & Core Architecture

| Area | Public / Customer Side | Admin / Store Back-Office Side |
| :--- | :--- | :--- |
| **Entry & Auth** | Customer Sign Up (math CAPTCHA), Sign In & **Forgot Password via Resend Email OTP** modal (`CustomerAuthModal`), Navbar quick **Sign In** / **Sign Up** buttons, IP rate limiting & JWT `httpOnly` cookie (`alharam_token`) | SVG CAPTCHA-protected staff/admin login at `/admin/login` (`/api/auth/captcha`, `/api/auth/login`) |
| **Ordering & Billing** | Live Tariff & Rate Calculator, Online Pickup Booking (`PickupBookingSection`), Printable Invoice & Razorpay Online Payment (`/invoice/[id]`) | Counter POS (`/admin/counter`) with garment tariff selection, inspection photo compression/upload (`Cloudinary`), discounts, and WhatsApp bill dispatch |
| **Tracking & Handover** | Real-time 5-stage garment tracking (`/track`, `CustomerHistoryModal`), **Customer-Only 4-Digit Delivery OTP** shown when `out_for_delivery` | Orders & Deliveries Pipeline (`/admin/orders`) with stage transitions, **Record Payment (`Mark Paid`)** modal, Ready SMS alerts, **OTP redaction** on Admin views, and **Verify & Deliver** modal |
| **CRM & Phone Hygiene** | Mobile numbers normalized automatically (`+91` / leading `0` stripped to 10 digits) on registration, login, and pickup booking | Unified **Customers List** (`/admin/customers`) deduplicating profiles by normalized phone with lifetime stats & quick actions (`Invoices`, `New Order`) |
| **Reviews & Ratings** | Interactive reviews showcase (`#reviews`) with rating summary; **signed-in customers** can submit new reviews (awaiting approval) | **Customer Reviews Management** (`/admin/reviews`): Admin-only approval/hiding, inline editing, direct creation, and deletion |
| **Store Configuration** | Dynamic rates & store contact details across footer/invoices | **Customisation Hub** (`/admin/settings`) for store info, `razorpay.me` payment URL, invoice prefix, max discount %, tax rate, and invoice T&Cs |

## How Everything Works (End-to-End Workflows)

### 1. Authentication, Sessions & Normalization
- **JWT Sessions ([`src/lib/auth.ts`](src/lib/auth.ts)):** Logins issue a 7-day signed JWT stored in the `alharam_token` cookie (`role`: `'admin' | 'counter_staff' | 'delivery' | 'customer'`). [`getCurrentUser()`](src/lib/auth.ts) verifies the token server-side in API routes; client UI state is hydrated via `/api/auth/me` inside [`CustomerAuthContext`](src/context/CustomerAuthContext.tsx).
- **CAPTCHA & Rate-Limit Guards:** Customer Sign Up (`/api/auth/register`) uses math CAPTCHA ([`/api/auth/math-captcha`](src/app/api/auth/math-captcha/route.ts)), while Customer Sign In (`/api/auth/customer-login`) skips CAPTCHA; both are protected by IP rate limiting ([`src/lib/rateLimit.ts`](src/lib/rateLimit.ts)). Admin login (`/api/auth/login`) uses SVG text CAPTCHA ([`/api/auth/captcha`](src/app/api/auth/captcha/route.ts)) plus IP rate limiting.
- **Forgot Password with Resend Email OTP Verification ([`src/lib/resend.ts`](src/lib/resend.ts)):** Customers can click "Forgot password?" in [`CustomerAuthModal`](src/components/CustomerAuthModal.tsx) to reset their password through a 3-step security flow strictly using their registered Gmail / Email address:
  1. **Request OTP ([`/api/auth/forgot-password`](src/app/api/auth/forgot-password/route.ts)):** Validates the registered Gmail / Email address (phone numbers are rejected), queries the customer profile strictly by email, enforces a strict daily limit of maximum 2 reset requests per user in 24 hours (preventing Resend API calls after the 2nd attempt), generates a 6-digit numeric OTP valid for 10 minutes, and dispatches a branded HTML email via Resend (`RESEND_API_KEY`, `RESEND_FROM_EMAIL`) without any phone number references in the footer.
  2. **Verify OTP ([`/api/auth/verify-reset-otp`](src/app/api/auth/verify-reset-otp/route.ts)):** Confirms the code against the registered email, clears the OTP to prevent replay, and issues a tamper-proof 15-minute signed JWT `resetToken`.
  3. **Reset Password ([`/api/auth/reset-password`](src/app/api/auth/reset-password/route.ts)):** Validates the `resetToken`, hashes the new password with bcrypt (`bcrypt.hash(pwd, 10)`), clears any residual tokens, and issues an authenticated session cookie (`alharam_token`) logging the customer in instantly.
- **10-Digit Mobile Hygiene ([`src/lib/phone.ts`](src/lib/phone.ts)):** [`normalizeIndianPhone`](src/lib/phone.ts) strips non-digits, leading zeros (`08745073655` → `8745073655`), and `91`/`+91` prefixes across UI inputs (`sanitizePhoneInput`), auth routes, pickup/POS order creation, WhatsApp URLs, and customer aggregation so one customer never splits into two records.

### 2. Pickup Booking, Counter POS & Garment Billing
- **Pricing Catalog (`ServiceItem`) & Specialty Range Items ([`src/lib/servicePricing.ts`](src/lib/servicePricing.ts)):** Categorized as `mens`, `womens`, `home`, and `laundry`. Supports distinct handling for specialty range-price garments (Women's `Suit 3Pcs`, Women's `Suit 2Pcs`, `Saree`, `Lehenga`, `Gown`, and Men's `Sherwani`) where pricing depends on fabric, layers, and embroidery:
  - **Specialty Range Items:** Replaces fixed amounts and 50% advances with **"Owner will connect with you"** badges and starting range references across the public Rate Calculator (`RateCalculator.tsx`), Estimate summary, and Digital Invoice (`/invoice/[id]`), setting estimate item rate to ₹0 (`Price on Inspection`).
  - **Standard Fixed Items:** Displays both the full rate and **50% Mandatory Advance** (e.g. `₹250 (50% Adv: ₹125)`) across Dry Clean and Steam Press columns.
  - **Admin Orders & Deliveries Dashboard ([`src/app/admin/orders`](src/app/admin/orders/page.tsx)):** Highlights orders containing range-price garments with prominent `📞 Owner to Connect (Range Price)` badges on desktop tables and mobile cards, and tags individual garment items with service types (`DC`, `Press`, `Laundry`) and `Range Quote` flags so staff and store owners immediately identify orders requiring customer follow-up.
- **Order Creation (`/api/orders/create`):** Generates sequential invoice numbers (`<invoicePrefix>-<YEAR>-<seq>`, e.g., `AHDC-2026-00368`), computes subtotals/discounts/taxes/balances, normalizes customer mobile numbers, omits empty optional fields & per-item `{ _id }` subdocuments, and saves compact `OrderInvoice` documents (rate-limited for guest/customer submissions).
- **Garment Inspection Photos ([`src/lib/imageCompression.ts`](src/lib/imageCompression.ts), [`src/lib/cloudinary.ts`](src/lib/cloudinary.ts), [`/api/cloudinary/sign`](src/app/api/cloudinary/sign/route.ts), [`/api/cloudinary/destroy`](src/app/api/cloudinary/destroy/route.ts)):** Counter staff compress garment condition photos client-side (800px max dimension, `<50 KB` WebP with small-image fast path), upload directly to Cloudinary using staff-only signed parameters, and clean up orphaned assets automatically if an unsubmitted photo or item row is removed.
- **Payments (Dual-Mode Razorpay + Counter Settlement):**
  - **Razorpay.me Instant Link Mode (Works Immediately):** When API keys (`RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET`) are still placeholders, `/api/payments/razorpay/create-order` returns `mode: 'payment_link'` pointing to the exact base `razorpay.me` handle URL (default `https://razorpay.me/@ashiyaalharamdrycleaner`, without appending `/<amount>` since Razorpay V2 handles reject path/query amount overrides). Customer digital invoices (`/invoice/[id]`) display 1-click Copy buttons for the due amount and required Comment reference (`Invoice #<number>`), [`src/lib/whatsapp.ts`](src/lib/whatsapp.ts) embeds the link + payment instructions in WhatsApp messages, and staff settle verified receipts in [`/admin/orders`](src/app/admin/orders/page.tsx) (`PATCH /api/orders/[id]/payment` with support for full payment, custom partial amounts, or **Settle Bill** to collect a partial sum and waive remaining balance to ₹0).
  - **Standard Razorpay Checkout + Mandatory 50% Advance Policy for Customers:** Restored the mandatory 50% minimum advance requirement across all customer digital invoice views. Customers viewing an invoice on [`/invoice/[id]`](src/app/invoice/[id]/page.tsx) without prior advance are presented with two strict choices: **Option 1: 50% Advance (Mandatory)** (e.g. `₹halfPayableAmount` with remaining due on delivery) and **Option 2: Full Payment (100%)** (zero balance on delivery), completely removing the custom payment input and ₹0 pay-on-delivery options from the customer view. Once 50% advance has been satisfied, customers can directly settle the remaining balance online. Backend route [`/api/payments/razorpay/create-order`](src/app/api/payments/razorpay/create-order/route.ts) enforces the 50% minimum advance rule before generating Razorpay orders, while Counter POS ([`/admin/counter`](src/app/admin/counter/page.tsx)) retains full flexibility for store staff to record custom walk-in cash/UPI payments.

### 3. Order Lifecycle, Alerts & Customer-Only Delivery OTP
1. Garments move through stages: `received` → `in_process` → `ready` → `out_for_delivery` → `delivered` (or `cancelled`).
2. **Ready Alerts:** Marking an order `ready` can automatically dispatch Fast2SMS notifications ([`src/lib/sms.ts`](src/lib/sms.ts)) and enables one-click WhatsApp alerts ([`src/lib/whatsapp.ts`](src/lib/whatsapp.ts)).
3. **Confidential Delivery OTP Generation:** When status switches to `out_for_delivery` in `PATCH /api/orders/[id]/status`, the server generates a random 4-digit `deliveryOtp` stored on the order.
4. **Strict Admin OTP Hiding:** `GET /api/orders` (`.select('-deliveryOtp')`), `PATCH /api/orders/[id]/status` (strips `deliveryOtp` and `expectedOtp`), `/admin/orders` UI (`Verify & Deliver`), and admin-triggered `out_for_delivery` WhatsApp messages **never expose the OTP to Admin or delivery boys**. Instead, WhatsApp directs the customer to their `/track` link.
5. **Customer View & Verification:** Only the customer views their 4-digit OTP on [`/track`](src/app/track/page.tsx) (via `/api/orders/[id]` or `/api/customer/orders?phone=...`), [`CustomerHistoryModal`](src/components/CustomerHistoryModal.tsx), and [`/invoice/[id]`](src/app/invoice/[id]/page.tsx). Upon doorstep delivery, the customer verbally shares that OTP; staff enter it in Admin **Verify & Deliver** (or use `admin_override` if the customer's phone is dead) to confirm `delivered`.

### 4. Unified Customers CRM & Password Security Management (`/admin/customers`)
- [`GET /api/admin/customers`](src/app/api/admin/customers/route.ts) (protected for staff `admin` / `counter_staff`) runs a MongoDB `$facet` + `$slice` aggregation pipeline to deduplicate normalized 10-digit mobile numbers, calculate KPI totals, and return paginated customer summaries (20 per page) with their latest 3 orders and live password reset stats. Opening **Invoices** lazily fetches full order history for that single customer (`?phone=...`), alongside the **New Order** quick action.
- **Admin Password & Security Control ([`/api/admin/customers/password`](src/app/api/admin/customers/password/route.ts)):** Store Admin can manage customer credentials directly from the Customers directory (`/admin/customers`):
  1. **Password Reset Activity & Quota Tracking:** Displays customer's daily OTP request count (with `Reset Blocked (2/2)` badges), lifetime password resets completed (`passwordResetCount`), and last reset timestamp (`lastPasswordResetAt`).
  2. **1-Click Daily Limit Unlock:** Allows Admin to instantly clear a customer's daily 2-attempt limit when locked out.
  3. **Direct Password Update with Show Password:** Admin can set a new customer password (with auto-generate strong password, copy to clipboard, and show/hide password toggle) hashed securely via bcrypt (`bcrypt.hash(pwd, 10)`).

### 5. Customer Reviews & Role-Based Moderation (`#reviews` & `/admin/reviews`)
- **Public View (`CustomerReviewsSection`):** Hydrated server-side on `HomePage` (`getCachedApprovedReviews`, seeded cleanly via [`scripts/seed.mjs`](scripts/seed.mjs)) and backed by cached `GET /api/reviews` responses showing average rating & approved count. When more than 3 approved reviews exist, switches from a static 3-column grid to an **auto-advancing 3-second responsive carousel** with left/right arrows, pagination dots, hover-pause, and touch swipe support.
- **Customer Creation (Pending Approval):** Unauthenticated clicks on **Sign in to Write a Review** open `CustomerAuthModal`; after login, the review modal opens automatically. Signed-in customers (`POST /api/reviews`) can submit reviews (`isApproved: false`, checked against past orders for `isVerifiedCustomer`), and see confirmation that their review awaits Admin approval.
- **Admin-Only Moderation (`/admin/reviews`):** Admin can filter **All / Pending / Published**, approve or hide reviews (`PATCH /api/reviews/[id]`), edit reviewer details/stars/comments (`editedByAdmin: true`), create pre-approved reviews, or delete reviews (`DELETE /api/reviews/[id]`). Non-admin requests to `?all=true`, `PATCH`, or `DELETE` return `401`/`403`.
